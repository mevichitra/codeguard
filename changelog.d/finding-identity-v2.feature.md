Baselines now match findings one to one with the new `codeguard/v2` identity: a set of keys built from the statement a finding sits in, compared strictest first. A baselined finding survives a renamed file, a renamed or extracted enclosing function, a renamed local and an edited line, while a second copy of a baselined statement is reported as new (a baseline entry used to hide every finding with the same fingerprint). `--baseline-strict` (or `baseline_strict = true`) reports matches the matcher had to guess about, such as a pasted copy, as new. Baseline files move to schema 2; older files still load, and `codeguard baseline update` converts them and now lets entries follow their findings. JSON output gains `identity` and `match`, SARIF `partialFingerprints` gains the v2 keys, and JavaScript and TypeScript findings get a scope.
